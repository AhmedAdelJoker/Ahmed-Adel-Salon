# تقرير فحص وتحسين صفحة bookings (الحجوزات)

> فرع `security/postgres-hardening` — فحص + إصلاحات صفحة «الحجوزات» (`/bookings`)
> نطاق الواجهة: `frontend/src/features/bookings/**` + `frontend/src/pages/cashier/Bookings.tsx`

---

## 1) ملخص تنفيذي

فحص شامل لصفحة الحجوزات كشف **10 مشاكل**، أبرزها:
استخدام `prompt()` الأصلي عند إعادة الجدولة (تجربة ضعيفة بلا اختيار خبير ولا معاينة)،
رسائل خطأ 409 غير موحّدة، غياب مؤشر تحميل التحديث اليدوي، عدم تمييز الأوقات المحجوزة،
شريط سعة بتقسيم لغوي خاطئ وبلا ARIA، عرض مئات البطاقات دفعة واحدة،
وفقدان بيانات النموذج عند إغلاق نافذة الإنشاء.
نُفذت خطة من 5 مراحل وجميع الفحوص «خضراء»:
`tsc` نظيف، فيتست **567/567**، i18n **7/7**، البناء الإنتاجي ناجح.

## 3) الخطة المنفذة (5 مراحل)

### Phase 1 — إعادة جدولة احترافية
- مكون جديد `RescheduleBookingDialog.tsx`:
  - حقل تاريخ + اختيار خبير مع إظهار الخبير الحالي.
  - جلب الأوقات الفعلية من `/appointments/available-slots`.
  - معاينة «من وقت X إلى وقت Y» قبل الحفظ + زر حفظ معطّل أثناء الإرسال.
- استبدال كامل لمسار `prompt` في `BookingsBoardContent.tsx`.
- تصدير المكون من `components/index.ts` مع استخدام `timeOnly` من الأداة الموحدة.

### Phase 2 — رسائل وأخطاء منسقة + a11y
- **رسالة 409 موحدة**: دالة `bookingApiErrorMessage(err, fallback)` في `utils/board.ts`:
  إذا كانت استجابة 409 → تُعرض رسالة الخادم العربية كما هي، وإلا رسالة موحدة
  «تعارض في الحجز مع موعد آخر لنفس الخبير…». توظفت في كل معالجات الكتابة:
  تفعيل، إعادة جدولة، تغيير حالة، نقل خبير، إلغاء، حفظ.
- **مؤشر تحميل**: نص «جارٍ التحديث…» + `aria-live="polite"` + `aria-busy` على زر التحديث.
- **تمييز الأوقات المحجوزة**: في `BookingFormDialog.tsx` للأوقات غير `slot.available`:
  شطب أحمر (`line-through`) + `title="محجوز — غير متاح"` + `aria-label={… محجوز}`.
- **شريط السعة `SalonCapacityBanner.tsx`**:
  - تقسيم عربي صحيح: «موعداً واحداً / موعدان / N مواعيد / N موعداً» بدل «N مواعيد» دائماً.
  - `%` مُقيّد ضمن 0..100 (حماية من قيمة خادم سالبة أو فوق 100).
  - شريط `role="progressbar"` + `aria-valuenow/min/max`.
- **A11y في `BookingCardFull.tsx`**: aria-label لأزرار تفعيل، تحويل POS، تعديل،
  إعادة جدولة، إلغاء، واتساب؛ واسم العميل (clickable) حصل على aria-label ديناميكي.

### Phase 3 — أداء + سلامة بيانات
- **Pagination على مستوى العرض**: `BookingsBoardContent.tsx` يعرض أول 24 بطاقة
  مع زر «عرض المزيد (N متبقية)»، يُعاد الاعتماد عند أي تغيير فلتر (via `useEffect`).
- **حفظ مسودة نموذج الإضافة محلياً**:
  دوال `readBookingDraft/writeBookingDraft` على `salonpro.bookings.createDraft.v1`.
  - أثناء فتح نافذة الإنشاء (لا تعديل) تُحفظ: الاسم، الهاتف، الخبير، الوقت، الخدمات،
    ملاحظات، مصدر الحجز، وضع العميل، العميل المُطابَق.
  - عند إعادة فتح `openCreate` تُستعاد المسودة (والتاريخ دائماً اليوم).
  - تُحذف المسودة تلقائياً بعد نجاح الحفظ.
  - كل عمليات التخزين bounded (try/catch) فلا تكسر المتصفحات المقيدة.

### Phase 4 — i18n شريط أدوات الحجوزات
- namespace جديد `bookings` في `src/i18n/index.ts` + ملفا `ar|en/bookings.json`.
- كل نصوص `BookingsToolbar.tsx` أصبحت عبر `t()`: البحث ومسحه، كل الخبراء،
  «إلى»، فلاتر التاريخ (مفاتيح مشتقة من `f.id`)، تبويبات الحالة (خريطة
  `TAB_LABEL_KEYS` لأن المعرّفات نفسها عربية في الحالة المحفوظة)،
  الفلترة السريعة، مسح التصفية، الشرائح (chips)، حالة الاتصال الحي،
  آخر تحديث/جارٍ التحديث (بمُعارضة `{{time}}`)، وزر التحديث و aria-label.
- ضوابط الترجمة `src/test/i18n.test.ts` تُسجَّل الـnamespace الجديد (7/7 خضراء).
- معرفات التبويبات تبقى عربية كما هي (بيانات محفوظة) — الترجمة على مستوى العرض فقط.

### Phase 5 — i18n موسّع لكل مكونات الحجوزات
- أقسام جديدة في `ar|en/bookings.json` لمفاتيح متكافئة:
  `card` (تفعيل/تحويل POS/تعديل/إعادة جدولة/إلغاء/واتساب وعناصر قائمته بـ`{{outs}}`،
  معرفة aria، «عميل غير ملتزم»، «غير متوفر»، «الخبير المسؤول»/«غير محدد»،
  «متأخر {{minutes}} دقيقة»، لافتة التأخير، «عرض أقل/عرض كافة الخدمات ({{count}})»،
  «(N د)»، مكتمل/ملغي، قيود الحجز السابق) — إضافة `status` لتسميات الحالات
  (قيد المراجعة/مؤكد/نشط بالاستقبال/مكتمل/ملغي) و`conflict.generic` و`toasts`.
- `utils/board.ts`: تسميات `statusConfig` صارت مفاتيح ترجمة (`status.*`)،
  و`bookingApiErrorMessage` يقبل رسالة تعارض مترجمة اختيارية من المستدعي
  (يبقى بديل عربي ثابت لو استُدعي خارج سياق React).
- ` BookingCardFull.tsx`، `BookingsBoardContent.tsx` (فارغ الشبكة والكانبان،
  «عرض المزيد (N متبقية)»، عدد حجوزات الخبير، «إيراد متوقع»)،
  `BookingFormDialog.tsx` (كامل النوافذ: عنوان/وصف/هاتف/العميل المسجل/عميل
  جديد/التاريخ/±15/أوقات محجوزة بنص وaria مع `{{time}}`/النهاية المتوقعة/
  «جاري الحساب...»/الخدمات/المبلغ/الملاحظات/الأزرار)، `RescheduleBookingDialog.tsx`
  (كامل)، `CancelBookingDialog.tsx` (أسباب الإلغاء الأربعة تُخزن كما قبل لكن
  تُعرض/تُبنى عبر الترجمة)، `SalonCapacityBanner.tsx` (الصفر: «لا حجوزات حتى
  الآن» + صيغ العدد موعود/موعدان/مواعيد — والجملتين `bookedToday`/`pressure`
  بقيم نصية)، `BookingsStatsGrid.tsx` (بطاقات الخمس)، `BookingsHeaderActions.tsx`
  (أزرار الترويسة)، وصفحة `pages/cashier/Bookings.tsx` (العنوان/الوصف/شارة
  الاتصال) وقسم `page` و`header` و`stats` في الترجمات.
- `hooks/useBookingsData.ts`: كل رسائل toast والتحقق صارت عبر `t()`
  (قسم `toasts.*`) مع `{{name}}` للاختيار، وأُضيف `t` إلى تبعيات
  الـ`useCallback` المعنية — الخدمات/القوالب المررة عبر API (منها قوالب
  واتساب في `board.ts` و`booking_pos_bridge` كبيانات لم تُمَس).

## 5) نتائج الفحوص النهائية
- `npx tsc --noEmit`: نظيف (تكرار بعد كل مرحلة).
- `npm run test:run`: **567/567** في 52 ملفاً (بعد Phase 5).
- ضوابط i18n: **7/7**.
- `npm run build`: ناجح (~4.5s).
- تحقق حي في المتصفح: العربية ترسم كل شيء كما يجب، والتبديل إلى الإنجليزية
  ثم العودة يعملان بصفر أخطاء console (شريط السعة، البطاقات، الإحصاءات،
  التبويبات كلها تترجم).
